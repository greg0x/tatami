# Edge cases

Failures reported against other window managers, each one checked against tatami. The reports are in
the issue trackers of AeroSpace, yabai, skhd, i3, sway, Amethyst, Rectangle, Hammerspoon and
komorebi. Every failure that can be reproduced against the engine has a scenario test. Most of what
failed is fixed, and the rest is under [Open](#open). What only the macOS shell (`src/macos`) can
get wrong is listed with what the shell does about it. [COMPLAINTS.md](COMPLAINTS.md) holds the
complaints from daily use that tatami started from; this is the wider list.

A link names a report of the same kind of failure. The cause found in that thread may differ, and
reports of one failure in several trackers share a row.

## How to read it

| Status | Meaning |
|---|---|
| tested | tatami does not have the failure, and the named test keeps it that way. |
| fixed | tatami had the failure. It is fixed in the engine, and a test named in the row fails without the fix. |
| fixed in the shell, not run under test | The fault was in `src/macos`, and the shell handles it now. The shell has no tests, so no test proves it. A test named in such a row covers the engine half. |
| no test | The engine handles it, or it is a choice of the design, as far as reading the code shows. No test of its own. |
| needs a real Mac | It depends on what macOS or an application really does, which the simulator cannot say. |
| open | Known and not handled. A test named in such a row covers the part that is done. |

Cases that have no counterpart in tatami are in the last section, [Does not apply](#does-not-apply).

Run the tests and the simulator:

```sh
./zig/zig build test                       # unit and scenario tests
./zig/zig build -Doptimize=ReleaseSafe     # builds zig-out/bin/tatami-sim
./zig-out/bin/tatami-sim <seed> <steps>    # one seed of the simulator, faults on
```

The scenario tests are in `src/scenarios.zig` and, by tracker, in `src/scenarios_aerospace.zig`,
`src/scenarios_yabai.zig` (yabai and skhd), `src/scenarios_i3.zig` (i3 and sway) and
`src/scenarios_macapps.zig` (Amethyst, Rectangle, Hammerspoon, komorebi). A few tests named here are
in `src/config.zig` and `src/sim.zig`. What the trackers did not report and reading, fuzzing
and hostile input found is tested in `src/scenarios_review.zig`, `src/scenarios_fuzz.zig`,
`src/scenarios_hostile.zig` and `src/scenarios_restart.zig`. Every test name is used once, so `grep -rn "<name>" src`
finds it. A scenario test runs the real engine against the simulated macOS with the random faults
switched off, so every expectation is exact; the simulator then runs generated workloads with the
faults on and checks its invariants after every quiet moment ([DESIGN.md](DESIGN.md)).

## Open

Known and not fixed, most important first. A heading that names the engine is a fault of the engine,
or needs a change there; everything else is work in the shell that is not done.

1. **A popup switches the workspace (engine and shell).** A popup of an application whose windows
   are on a hidden workspace closes, focus falls to one of those windows, and the workspace follows.
   The engine cannot tell this from cmd-tab: the shell does not say whether the user caused a focus
   change. [AeroSpace #328](https://github.com/nikitabobko/AeroSpace/issues/328),
   [AeroSpace #481](https://github.com/nikitabobko/AeroSpace/issues/481),
   [AeroSpace #1560](https://github.com/nikitabobko/AeroSpace/issues/1560),
   [i3 #1426](https://github.com/i3/i3/issues/1426),
   [i3 #3979](https://github.com/i3/i3/issues/3979).
2. **Keys go to a hidden window.** On an empty workspace the keyboard still belongs to the parked
   window of the workspace that was left. Nothing takes it away.
   [AeroSpace #301](https://github.com/nikitabobko/AeroSpace/issues/301).
3. **The wrong window of an application gets focus.** The shell sets main, raises, and then brings
   the whole application to the front, so macOS can raise all its windows or make another one key,
   on another display or workspace. The result is not checked.
   [AeroSpace #101](https://github.com/nikitabobko/AeroSpace/issues/101),
   [AeroSpace #247](https://github.com/nikitabobko/AeroSpace/issues/247),
   [yabai #102](https://github.com/asmvik/yabai/issues/102),
   [Hammerspoon #370](https://github.com/Hammerspoon/hammerspoon/issues/370).
4. **Ghost tiles of a living application.** A window that is hidden instead of closed (Electron
   close-to-tray, palettes, Quick Look) keeps its tile: Accessibility still has it, and the shell
   does not compare what it tracks with what is on screen.
   [AeroSpace #77](https://github.com/nikitabobko/AeroSpace/issues/77),
   [yabai #2431](https://github.com/asmvik/yabai/issues/2431),
   [Amethyst #830](https://github.com/ianyh/Amethyst/issues/830),
   [Hammerspoon #3295](https://github.com/Hammerspoon/hammerspoon/issues/3295).
5. **Lock screen and sleep.** The shell learns that the displays sleep only from an empty display
   list; it listens for the unlock, not for sleep or wake. While the screen is locked a window that
   Accessibility reports as gone still counts as closed.
   [AeroSpace #771](https://github.com/nikitabobko/AeroSpace/issues/771),
   [AeroSpace #814](https://github.com/nikitabobko/AeroSpace/issues/814),
   [AeroSpace #2234](https://github.com/nikitabobko/AeroSpace/issues/2234).
6. **Native Spaces, Mission Control, Stage Manager.** The shell does not follow the active Space. A
   window on another Space is found only when it takes focus, a window dragged to another Space
   keeps its tile, and tiles sit under the Stage Manager strip.
   [AeroSpace #91](https://github.com/nikitabobko/AeroSpace/issues/91),
   [AeroSpace #551](https://github.com/nikitabobko/AeroSpace/issues/551),
   [yabai #1367](https://github.com/asmvik/yabai/issues/1367),
   [yabai #1580](https://github.com/asmvik/yabai/issues/1580),
   [Amethyst #11](https://github.com/ianyh/Amethyst/issues/11),
   [Amethyst #1258](https://github.com/ianyh/Amethyst/issues/1258).
7. **Tab detection.** Tabs are recognised by equal frames when a window appears. A window of another
   Space can be taken for a tab, tabs already merged at start are not recognised, and a tab being
   torn off is tiled under the pointer.
   [AeroSpace #68](https://github.com/nikitabobko/AeroSpace/issues/68),
   [AeroSpace #1001](https://github.com/nikitabobko/AeroSpace/issues/1001),
   [AeroSpace discussion #2214](https://github.com/nikitabobko/AeroSpace/discussions/2214),
   [yabai #233](https://github.com/asmvik/yabai/issues/233),
   [Amethyst #1613](https://github.com/ianyh/Amethyst/issues/1613).
8. **Windows without a title bar.** Terminals with decorations off, Wine and windows with an unknown
   subrole are dropped as popups before any rule sees them, so no rule can tile them.
   [AeroSpace #166](https://github.com/nikitabobko/AeroSpace/issues/166),
   [AeroSpace #208](https://github.com/nikitabobko/AeroSpace/issues/208),
   [Amethyst #200](https://github.com/ianyh/Amethyst/issues/200),
   [Amethyst #300](https://github.com/ianyh/Amethyst/issues/300).
9. **A display between two taller ones (engine).** Its hidden windows show on a neighbour: no bottom
   corner and no side is free.
   [AeroSpace discussion #2102](https://github.com/nikitabobko/AeroSpace/discussions/2102),
   [Amethyst #1436](https://github.com/ianyh/Amethyst/issues/1436),
   [komorebi #1053](https://github.com/LGUG2Z/komorebi/issues/1053),
   [komorebi #1056](https://github.com/LGUG2Z/komorebi/issues/1056).
10. **Keyboard layouts.** Bindings are ANSI key positions, not the letters of the layout in use, and
    the default option-number bindings take characters away on German, Nordic and similar layouts.
    [skhd #59](https://github.com/asmvik/skhd/issues/59),
    [skhd #69](https://github.com/asmvik/skhd/issues/69),
    [skhd #281](https://github.com/asmvik/skhd/issues/281),
    [skhd #358](https://github.com/asmvik/skhd/issues/358).
11. **Startup with a hung application.** Finding a window makes eight Accessibility calls without
    stopping at the first timeout, so a hung application with N windows holds the start for about N
    times 2 s. [Amethyst #1757](https://github.com/ianyh/Amethyst/issues/1757),
    [Hammerspoon #2596](https://github.com/Hammerspoon/hammerspoon/issues/2596),
    [Hammerspoon #3421](https://github.com/Hammerspoon/hammerspoon/issues/3421).
12. **A stale drag report (engine).** A mouse-drag report that arrives after `tile` or
    `toggle float` is read as a resize of the new tile. The shell could drop the report of a drag
    for a window that was sent a frame after the drag began.
    [i3 #1098](https://github.com/i3/i3/issues/1098),
    [i3 #1627](https://github.com/i3/i3/issues/1627).
13. **Dialogs and popups of the focused application.** The shell does not say which window a dialog

    [sway #3007](https://github.com/swaywm/sway/issues/3007),
    [sway #4797](https://github.com/swaywm/sway/issues/4797).

    [yabai #1545](https://github.com/asmvik/yabai/issues/1545).
15. **Labels (engine).** A label on a window whose native tab is the one showing answers conflict to

## Needs a real Mac

The tests run the engine against a simulated macOS. Nothing under `src/macos` is built or run by
them, and [README.md](../README.md) lists what has been checked live. The simulator cannot prove:

- Anything in the shell, including every fix in the shell listed above.
- The order in which macOS sends notices, and the ones it drops. The simulator always reports a
  close before the focus change that follows it, so the close tests prove the guard in the engine,
  not the race.
- Which window macOS makes key when an application is brought to the front, and which windows it
  raises with it.
- What macOS does to windows at sleep, wake, lock and replug: which ones it moves, and whether it
  reports an empty display list at all. The tests hand the engine an empty list themselves.
- Native fullscreen, a display that changes resolution, the Dock taking room, a closed lid, a
  display under a new id: the simulator has no such events. The tests step the engine with them
  directly and perform the effects on the simulated windows, which proves the layout and the number
  of frames, not the order of effects.
- How particular applications describe their windows: subroles that arrive late or are wrong,
  windows without a title bar, dialogs that claim to be standard windows, hidden palettes, Electron
  windows that hide instead of closing.
- Tab detection, which the shell infers from frames, and a tab being torn off under the pointer.
- Native Spaces, Mission Control, Show Desktop and Stage Manager.
- Parked windows as macOS shows them: the sliver, Mission Control thumbnails, screenshots, whether
  an application keeps drawing while parked, and whether a later macOS moves a window parked at a
  corner back on screen.
